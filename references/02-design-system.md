# 2. Дизайн-система в теме

## Источник правды — tokens.css

Все визуальные решения — CSS-переменные в `assets/css/tokens.css`:

```css
:root,[data-theme=light]{ --surface:#f6f5f1; --surface-raised:#fff; --ink:#1a1f1d; --ink-muted:#545b57;
  --accent:#334862; --accent-hover:#26374c; --on-accent:#fff; --success:#97ca58; --danger:#b42318; --focus:#334862; … }
[data-theme=dark]{ --surface:#121614; --ink:#eceeea; --accent:#8fa8c8; --focus:#f2b233; … }
:root{ --space-1:4px; … --space-9:96px; --radius-sm:6px; --radius-md:10px; --radius-pill:999px;
  --container:1160px; --measure:680px; --header-height:68px; --control-height:48px;
  --font-sans:"Onest",system-ui,sans-serif; --font-mono:"JetBrains Mono",ui-monospace,monospace; }
```

Правила:

- **Семантические имена** (`surface`, `ink`, `accent`, `line`, `danger-soft`), а не «blue-500». Тёмная тема
  переопределяет те же имена — компоненты не знают, какая тема включена.
- **Пары «фон — текст на нём»** (`--accent` / `--on-accent`, `--signal` / `--on-signal`) задаются явно и
  проверяются на контраст ≥ 4.5:1 в обеих темах. Мягкие фоны (`*-soft`) имеют свой цвет текста (`*-ink`).
- **Шкала отступов 4/8** (4, 8, 12, 16, 24, 32, 48, 64, 96) и не больше 4 радиусов. Новые значения не
  придумываются в компоненте — сначала добавляется токен.
- Если макет пришёл из дизайн-инструмента со своим `tokens.css` — файл копируется как есть (в kalaganov5 —
  из `project/ds/tokens.css`), чтобы сравнение с макетом было один-в-один.

## theme.json повторяет токены

- `settings.color.palette` — те же слаги и значения, что светлая тема в `tokens.css`; подписи — понятные
  владельцу («Фон карточки», «Синий · действие»).
- `defaultPalette/defaultGradients/defaultDuotone: false`, `custom: false`, `customGradient: false`,
  `typography.customFontSize: false`, `defaultFontSizes: false`, `fluid: false` — владелец выбирает только из
  системы и не может «сломать» стиль случайным цветом.
- `fontSizes` — шкала проекта с подписями «19 · лид, H3».
- `layout.contentSize` = ширина текста (`--measure`), `wideSize` = контейнер (`--container`).
- **`appearanceTools: false`, нужные инструменты включаются по одному.** `appearanceTools: true` открывает
  владельцу рамки, тени, межбуквенный интервал, минимальную высоту, позиционирование — всё мимо дизайн-системы.
  Включены: внутренние отступы и `blockGap` (пресеты `spacingSizes` из шкалы `--space-*`, своё значение
  ввести нельзя), скругление (пресеты `radiusSizes` из `--radius-*`), начертание и насыщенность шрифта,
  пропорции картинки. Выключены: цвет, ширина и стиль рамки, тени, `position: sticky`, буквица, межстрочный
  интервал, регистр, отступ первой строки, колонки текста, фон-картинка и градиент, лайтбокс, ширины
  макета в редакторе.
- Каждый ключ сверяется со списком допустимых настроек текущего WordPress (`WP_Theme_JSON::VALID_SETTINGS`):
  неизвестный ключ WordPress молча игнорирует.
- `styles` в `theme.json` не дублирует `tokens.css`: значения дизайна живут в одном месте.

Чтобы пресеты WordPress (`has-ink-color`, `has-surface-background-color`) тоже переключались в тёмной теме,
в `base.css` они перенаправлены на переменные:

```css
body { --wp--preset--color--surface: var(--surface); --wp--preset--color--ink: var(--ink); /* …каждый слаг палитры */ }
```

## Тёмная тема без мигания

- Выбор хранится в `localStorage` (`acme-theme`: `light` | `dark` | нет — как в системе).
- Встроенный скрипт в `wp_head` с приоритетом 1 ставит `data-theme` и `color-scheme` на `<html>` до отрисовки:

```php
echo "<script>(function(){try{var t=localStorage.getItem('acme-theme');var d=t==='dark'||(t!=='light'&&matchMedia('(prefers-color-scheme: dark)').matches);var r=document.documentElement;r.dataset.theme=d?'dark':'light';r.style.colorScheme=d?'dark':'light';}catch(e){}})();</script>";
```

- Логотип и иконки — SVG с `fill="currentColor"` или цветами из переменных (`--logo`, `--logo-accent`).

## Шрифты — локально

- Variable-woff2, разбитые по `unicode-range` (latin, latin-ext, cyrillic, cyrillic-ext), лежат в
  `assets/fonts/` вместе с лицензией OFL. `font-display: swap`.
- `<link rel="preload" as="font" crossorigin>` — только для 1–2 файлов основного начертания основных
  алфавитов сайта (иначе preload отнимает полосу у LCP).
- Google Fonts не подключаются: внешний домен, лишнее соединение, вопросы GDPR.
- Те же файлы используют генераторы обложек (через base64 или URL темы), чтобы обложки совпадали с сайтом.

## CSS: структура и соглашения

CSS лежит там, где живёт то, что он оформляет. Один `site.css` на 700+ строк читать и править невозможно:
правка карточки требует поиска по всему файлу, а стили всех блоков грузятся на каждой странице.

| Файл | Что в нём | Где подключается |
|---|---|---|
| `assets/css/fonts.css` | `@font-face` | везде |
| `assets/css/tokens.css` | цвета, шрифты, отступы — единственный источник значений | везде |
| `assets/css/base.css` | основа, типографика, секции, заголовок страницы, служебные классы | везде |
| `assets/css/core-blocks.css` | стили дизайн-системы для core-блоков (`is-style-*`) | везде |
| `assets/css/components.css` | общие для нескольких блоков классы: логотип, карточка, превью YouTube, лента | везде |
| `blocks/<имя>/style.css` | вид одного блока темы | только на страницах с этим блоком |
| `assets/css/editor.css` | поправки холста редактора | только в редакторе |

- Список общих файлов — одна константа `ACME_BASE_STYLES` (`inc/assets.php`): по ней подключаются стили на сайте,
  в редакторе (`add_editor_style()`) и считается бюджет веса.
- Стиль блока объявлен в `block.json`: `"style": "file:./style.css"`. WordPress встраивает его в `<head>` до
  отрисовки, поэтому шапка и подвал (части шаблона) не мигают. `inc/assets.php` ставит стили блоков после общих
  файлов — иначе каскад был бы обратным — и даёт им версию «версия темы + время изменения файлов блока», чтобы
  годовой кеш браузера не отдавал старый CSS после деплоя.
- Класс нужен двум и более блокам — он переезжает в `components.css`.
- Компоненты дизайн-системы, пришедшие с макетом (`bundle.css`), — отдельным общим файлом в `ACME_BASE_STYLES`.

Соглашения:

- **Одно объявление на строку, вложенность не глубже двух уровней, классы с префиксом `acme-`**, состояния —
  `is-*`/`has-*` (проверяет Stylelint, `npm run check`). Оформление — Prettier, руками не выравнивают.

- **Отступы между элементами задаёт сетка** (`display:grid; gap`) родителя, у текстовых элементов внутри
  `main` — `margin: 0`. Так Gutenberg не добавляет свои поля, а редактор и сайт совпадают.
  `add_theme_support('disable-layout-styles')` — WordPress не генерирует свои layout-отступы.
- Ритм секций — `clamp()`: `--acme-gut: clamp(16px, 4vw, 24px)`, `--acme-sec: clamp(48px, 8vw, 96px)`.
- Классы-утилиты стека: `.acme-stack-16`, `.acme-stack-32` (`display:grid; gap:…`) — ими собираются группы в
  редакторе через «Дополнительные CSS-классы».
- Брейкпоинты — несколько фиксированных значений (например, 480, 760, 860, 1024, 1100), записываются как
  `max-width: 859.98px`, чтобы не было «дыры» в 1 px. Список брейкпоинтов — в Style Guide.
- `:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px; }` глобально.
- `@media (prefers-reduced-motion: reduce)` — анимации и плавная прокрутка выключаются.
- `[hidden] { display: none !important; }` — JS прячет элементы атрибутом `hidden`, а не классами.
- Комментарий у каждого неочевидного правила: почему значение такое («не ниже .85: иначе серый текст теряет
  контраст 4.5:1»).

## Брендбук, Style Guide, Компоненты

Три служебные страницы (по ссылке, `noindex`, не в карте сайта и меню) — для владельца, дизайнера и подрядчиков:

- **Брендбук** — позиционирование, логотип (версии, поле, запреты), цвета с HEX/RGB/CMYK, шрифты, фотостиль,
  аватары и обложки для соцсетей, архив `brand-kit.zip`.
- **Style Guide** — цвета обеих тем и контраст пар, типографика, отступы, сетка, иконки, состояния, брейкпоинты.
  Цвета и контраст считаются прямо из `tokens.css` (PHP читает файл и парсит переменные) — поменяли токен,
  страница обновилась.
- **Компоненты** — каждый компонент: живой пример (отрисован темой), как собрать в редакторе, какие поля
  редактируются, разметка Gutenberg и итоговый HTML с кнопкой «Копировать». Те же варианты зарегистрированы
  паттернами в категории «<сайт> · компоненты».

Это необязательный модуль, но он резко снижает число вопросов «а как сделать такой же блок».
