# 9. Формы, заявки, аналитика, cookie

## Форма заявки: Contact Form 7 + свой слой

CF7 выбран потому, что надёжно отправляет почту, проходит обновления WordPress и знаком владельцам. Всё
остальное — в плагине данных, без Flamingo и CF7-аддонов.

- **Формы создаёт импорт**: по одной на язык («Заявка · RU/EN/ES»), ID в опции `acme_cf7_forms` [lang => id],
  мета `acme_imported`. Шаблон формы — функция `acme_cf7_form_body( $strings, $urls )`: вёрстка как в макете
  (поля, подписи, согласие со ссылками на документы своего языка, скрытое поле-ловушка `website-hp`).
- Письмо: тема «Заявка с сайта: [your-name]», получатель `[_site_admin_email]` (владелец меняет в CF7),
  отправитель `wordpress@[_site_domain]`, в теле — язык и страница `[_url]`.
- `acceptance_as_validation: on`; автоматические `<p>/<br>` выключены для своих форм (`wpcf7_autop_or_not`).
- Блок темы `acme/lead-form` выводит форму языка страницы (`formId: 0` → по языку), заголовок и подзаголовок —
  атрибуты блока.
- Лишнюю «Контактную форму 1», которую CF7 создаёт при включении, `remote.sh` удаляет после первого импорта.

### Валидация

Свои правила и тексты ошибок (как в макете), фильтр `wpcf7_validate` с приоритетом 20: имя и контакт
(телефон / @telegram / e-mail) — в каркасе; в kalaganov5 ещё адрес сайта, обязательность которого задаёт блок
формы через скрытое поле. Тексты ошибок — строки интерфейса на языке формы. Подсветка у поля (`.is-error`) и
объявление ошибок — в `site.js`, как в макете.

### Антиспам без капчи

`wpcf7_spam`: заполнено поле-ловушка → спам; больше 5 отправок с одного IP за 10 минут (транзиент по
`md5(ip)`) → спам. Капча не нужна большинству небольших сайтов и мешает конверсии.

### Заявки сохраняются на сайте

`wpcf7_submit` со статусом `mail_sent` **или `mail_failed`** → запись типа `acme_lead` (`post_status: private`):
заголовок «Имя — контакт», текст — сообщение, мета: контакт, сайт, страница, язык. Колонки в списке «Заявки».
Сохранять нужно и при `mail_failed`: заявка как раз страхует от сломанной почты. (Хук `wpcf7_mail_sent`, как было
в kalaganov5, срабатывает только при успешном письме — тогда при сбое почты заявка теряется.)

### Копия в Telegram

Если в настройках есть токен бота и `chat_id`: `wp_remote_post( 'https://api.telegram.org/bot<token>/sendMessage',
[ 'timeout' => 5, 'blocking' => false, … ] )` — неблокирующе, посетитель не ждёт Telegram. Токен и chat_id
можно задать секретами деплоя (`TG_BOT_TOKEN`, `TG_CHAT_ID`) — тогда деплой пишет их в настройки.

Ссылки на Telegram со страниц статей — с меткой источника: `https://t.me/<user>?start=blog_<slug>`.

### Тестовый сайт

При копии боевого на тестовый заявки удаляются (личные данные), если не включено «оставить».
Реальная отправка почты на тестовом не проверяется — проверяется сохранение заявки (`tools/qa/interact.js`).

## Окно cookie (тема)

- Разметка — в блоке подвала (`blocks/site-footer/render.php`), поведение — в его `view.js` (`"viewScript"` в
  `block.json`): скрипт грузится только на сайте, в редакторе окна нет.
- Три кнопки: «Принять всё», «Только необходимые», «Настроить» (переключатели «Аналитика», «Маркетинг»).
- Выбор хранится в `localStorage` (`acme-consent`: `{ v: 1, necessary: true, analytics, marketing, ts }`)
  12 месяцев; после выбора — событие `window.dispatchEvent(new CustomEvent('acme-consent', { detail }))` и
  `window.acmeConsent`.
- Пока окно открыто, плавающие элементы (виджеты, кнопка мессенджера) скрыты — они не перекрывают окно.
- В подвале — ссылка «Настройки cookie», открывающая окно снова.
- QA-скрипты ставят согласие заранее (`addInitScript` → `localStorage`), чтобы окно не мешало проверкам.

## Google Tag Manager + Consent Mode v2 (плагин)

`inc/analytics.php`, ID контейнера в настройках. Выводится только если:

- окружение `production` (`wp_get_environment_type()`) **и** сайт открыт (`blog_public`) — или включено
  «и на тестовом»;
- не админка, не предпросмотр, посетитель **не** может редактировать записи (редакторы не портят статистику).

В `<head>` (приоритет 1):

```js
gtag('consent', 'default', { analytics_storage: 'denied', ad_storage: 'denied', ad_user_data: 'denied',
  ad_personalization: 'denied', functionality_storage: 'granted', security_storage: 'granted', wait_for_update: 500 });
// сохранённый выбор (не старше года) → gtag('consent', 'update', …)
// событие acme-consent → gtag('consent', 'update', …) + dataLayer.push({ event: 'acme_consent_update', acme_analytics, acme_marketing })
// сам gtm.js — после первого pointerdown/keydown/scroll/touchstart/mousemove или через 3 с после load
```

`<noscript>`-iframe — на `wp_body_open`.

В GTM: теги Google (GA4, Ads) понимают Consent Mode сами; **Яндекс Метрика и другие** — с условием
«Дополнительные проверки согласия → analytics_storage» или по событию `acme_consent_update` с
`acme_analytics = true`. В Метрике — фильтр переходов из ИИ-сервисов (рефереры chatgpt.com, perplexity.ai,
gemini.google.com, alice.yandex.ru).

Потери от отложенной загрузки — только посетители, ушедшие в первые секунды без единого действия.
