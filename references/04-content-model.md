# 4. Модель контента: типы записей, поля, настройки

## Типы записей

Регистрируются в плагине (`inc/post-types.php`) на `init` с приоритетом 5 (раньше темы и Polylang).

| Вид | Настройки | Пример |
|---|---|---|
| Публичный со страницами | `public: true`, `has_archive: '<раздел>'`, `rewrite: ['slug' => '<раздел>', 'with_front' => false]`, `show_in_rest: true` | услуги `/services/…`, кейсы `/cases/…` |
| Данные без страниц | `public: false`, `show_ui: true`, `publicly_queryable: false`, `exclude_from_search: true` | отзывы, курсы, история заказов — выводятся блоками |
| Входящие (заявки) | `public: false`, `show_in_rest: false`, `capabilities: ['create_posts' => 'do_not_allow']`, `map_meta_cap: true` | заявки с формы — нельзя создать руками, видно только в админке |

- `supports` — минимум нужного; `revisions` у редактируемого контента; `page-attributes` — если важен порядок.
- Разделы/рубрики своих типов — таксономия с `public: false`, `rewrite: false`, если у разделов нет своих
  страниц; у терминов — term meta (`acme_key`, `acme_order`, `acme_hidden`).
- Подписи — функция `acme_labels( 'Услуги', 'Услуга' )`, на языке владельца.
- Колонки списка в админке (`manage_<type>_posts_columns`) — для заявок: имя, контакт, страница, дата.
- `register_activation_hook` вызывает регистрацию и `flush_rewrite_rules()`.
- У каждой записи, созданной импортом, есть `acme_key` (стабильный ключ: `podderzhka`, `pochta`) —
  по нему ищут записи код, редиректы, обложки, меню. ID меняется между сайтами, ключ — нет.

## Поля без ACF: схема → мета → панель

Одна функция описывает все поля всех типов:

```php
function acme_meta_schema() {
	return array(
		'post' => array(
			'acme_service' => array( 'service', 'Услуга по теме (пусто — подберётся сама)' ),
			'acme_pillar'  => array( 'boolean', 'Руководство рубрики' ),
			'acme_updated' => array( 'date', 'Дата обновления', null, 'Обновление статьи' ),
			'acme_changes' => array( 'rows', 'Что изменилось, 1–4 строки', array(
				'max'    => 4,
				'fields' => array(
					array( 'text', 'Текст, до 80 символов', 'text' ),
					array( 'type', 'Тип', 'new:+ новый раздел|upd:↻ обновлено' ),
				),
			), 'Обновление статьи' ),
		),
		'acme_service' => array(
			'acme_short' => array( 'string', 'Короткое название (меню, поиск)' ),
			'acme_price' => array( 'string', 'Цена в меню' ),
			'acme_kw'    => array( 'string', 'Слова для поиска по услугам' ),
		),
	);
}
```

Формат поля: `[ тип, подпись, параметры, панель ]`. Типы: `string`, `integer`, `boolean`, `date`,
`service`/`post` (выпадающий список записей → integer ID), `rows` (повторяющиеся строки → массив объектов).
Поля без панели попадают в панель «Поля <сайт>».

Из схемы:

1. `register_post_meta( $type, $key, [ type, single: true, show_in_rest: true, auth_callback: edit_posts ] )`;
   у `rows` — `type: array`, `default: []` и `show_in_rest.schema` с `items.properties` (иначе REST не
   сохранит массив объектов).
2. `inc/editor.php` на `enqueue_block_editor_assets` подключает `assets/meta-panel.js` для типов, у которых
   есть схема, и передаёт `window.ACME_META = schema[type]` (+ списки услуг/статей на языке записи для
   выпадающих списков). Версия скрипта — `filemtime`, чтобы редактор не держал старый файл в кеше.
3. `meta-panel.js` регистрирует `PluginDocumentSettingPanel` на каждую группу и строит контролы по типам.
   Длинные строки (по маске ключа) — `TextareaControl`.

Добавить поле = одна строка в схеме. Никакого нового JS.

Поля рубрик (term meta) выводятся на страницах «Записи → Рубрики» через `category_add_form_fields` /
`category_edit_form_fields` и сохраняются на `created_category`/`edited_category`.

## Настройки сайта

`inc/settings.php` — страница «Настройки → <Сайт>», одна опция-массив `acme_settings`:

```php
function acme_settings_fields() {
	return array(
		'Контакты и профили' => array( 'telegram_url' => 'Telegram: ссылка', 'email' => 'Email', … ),
		'Рабочее время'      => array( 'work_tz' => 'Часовой пояс', 'work_from' => 'Начало, час', 'work_to' => 'Конец, час' ),
		'Заявки'             => array( 'tg_bot_token' => 'Telegram-бот: токен', 'tg_chat_id' => 'chat_id' ),
		'Аналитика'          => array( 'gtm_id' => 'ID контейнера GTM', 'gtm_test' => 'И на тестовом: 1/0' ),
	);
}
```

- Значения по умолчанию — `acme_settings_defaults()` (тип значения по умолчанию задаёт санитайзер: int →
  `(int)`, иначе `sanitize_text_field`). Чтение — `acme_setting( 'email' )` (опция поверх умолчаний).
- Поле токена — `type="password"`, `autocomplete="off"`.
- **Роли служебных страниц** (`acme_roles`: `home`, `prices`, `about`, `contacts`, `blog`, документы) —
  на той же странице выпадающими списками. Код получает адрес через `acme_role_url( 'contacts', $lang )`,
  а не по слагу: владелец может переименовать страницу, ссылки не сломаются.
- Сохранение настроек, цен, меню, строк и настроек Rank Math сбрасывает кеш страниц целиком
  (`inc/cache.php`): эти данные видны на каждой странице, а плагин кеша чистит только изменённую запись.

## Переменные в тексте (цены и т. п.)

Значение, которое повторяется в десятках мест и меняется, — метка `{{price:hour}}` в тексте:

- значения по умолчанию — `content/prices.php` `[ key => [ label, ru, en, es ] ]`; поверх — опция
  `acme_prices` со страницы «Настройки → Цены» (таблица ключ × язык, последняя строка — новая цена);
- замена на сайте — фильтры `render_block` (приоритет 20), `the_title`, `get_the_excerpt`,
  `pre_get_document_title`, `document_title_parts`, SEO-фильтры Rank Math (title, description, OG, Twitter),
  `rank_math/json_ld` (рекурсивно), подписи `acme_t()`;
- **только вне админки** (`! is_admin() || wp_doing_ajax()`): в редакторе метка видна и редактируема;
- нет значения — метка остаётся как есть (видно, что забыли заполнить).

Тот же механизм подходит для телефона, адреса, «лет опыта», числа клиентов.

## Записи как ссылки, а не адреса

Везде, где одна запись ссылается на другую (услуга статьи, «Читайте также», цель редиректа, пункт меню),
хранится **ID записи или стабильный ключ** и строится `get_permalink()` в момент вывода. Тогда смена слага
или переимпорт не ломают ссылки.

## Обложки записей

У каждой записи, которая может уйти в соцсети, — изображение записи 1200×630:

- генератор `tools/build-covers.js` (Playwright + HTML-макет с фирменными шрифтами и знаком) пакетно
  рендерит `content/covers/<тип>-<ключ>-<язык>.jpg`;
- `wp acme covers [--force]` ставит обложку только записям без своего изображения; `--force` обновляет
  только сгенерированные (помечены мета), не трогая загруженные владельцем;
- в админке — тот же макет на `<canvas>` (`assets/cover-tool.js`): панель «Обложка» в редакторе и страница
  «Медиафайлы → Обложка», кнопка «Поставить изображением записи». Два генератора делят один макет — при
  изменении меняются оба.
