# 12. Бриф и чек-листы

## Бриф (заполнить до начала)

```
Проект:            название, домен боевой, домен тестовый (dev.<домен>)
Префикс кода:      2–6 латинских букв (acme)
Владелец:          кто правит контент, язык админки
Языки:             основной + остальные (адреса: / и /en/ …)
Источник дизайна:  прототип HTML / Figma / Claude Design / готовый сайт; где лежит
Страницы:          список служебных (главная, цены, о нас, контакты, отзывы, блог, документы)
Типы контента:     услуги / товары-витрина / кейсы / отзывы / команда / курсы … — поля каждого
Формы:             какие, куда приходят (почта, Telegram), обязательные поля
Интеграции:        GTM, Метрика, GA4, CRM, мессенджеры, видео
Старый сайт:       есть? WordPress? экспорт, uploads, список адресов для 301
Хостинг:           SSH есть? путь к сайту, PHP-версия, rsync, cron, доступ к MySQL
SEO:               Rank Math да/нет, Person или Organization, профили, регион
Цены:              в тексте как переменные? валюты по языкам
Ограничения:       сроки, бюджет на плагины, юридические требования (152-ФЗ, GDPR)
```

## Новый проект: от нуля до тестового сайта

- [ ] Бриф заполнен, префикс выбран, домены и хостинг известны
- [ ] `scaffold.js` → новый репозиторий, `git init`, первый коммит каркаса
- [ ] Макет/прототип положен в `project/` (если есть), его README и переписка прочитаны
- [ ] `tokens.css` из макета; `theme.json` палитра и размеры = токены; шрифты локально + лицензии
- [ ] `style.css` (название, описание, версия), `screenshot.png` 1200×900
- [ ] Типы записей и `acme_meta_schema()`; настройки сайта; роли служебных страниц
- [ ] Шапка, подвал, крошки, форма — блоки темы; шаблоны для каждого типа
- [ ] Блоки секций главной и типовых страниц; паттерн «полная страница» для каждого типа
- [ ] Строки интерфейса на всех языках; меню по областям
- [ ] `build-content.js` → `content.json`; `wp acme import` локально без ошибок; `--force` повторяемо
- [ ] Редактор: запись открывается без шаблона, заголовок правится в поле заголовка, клик в любой абзац
  работает; `editor-usability.js` и `editor-validity.js` — PASS
- [ ] SEO: `wp acme seo` (версия 1), JSON-LD, robots, llms.txt; noindex служебного
- [ ] Формы: отправка, заявка в админке, Telegram; ошибки на всех языках
- [ ] GTM + Consent Mode; окно cookie; документы (политика, согласие, cookie)
- [ ] CI зелёный; окружение `test` и секреты; деплой на тестовый; проверка страниц прошла
- [ ] Обход 360/1280 без проблем; сценарии интерфейса PASS; блоки в редакторе valid
- [ ] README: установка, деплой, «где что править», чего не делать; CLAUDE.md; TODO.md

## Перед запуском боевого

- [ ] Окружение `production`: отдельные секреты, свой SSH-ключ, Required reviewers (по желанию)
- [ ] Перенос старого сайта на тестовом прошёл; `legacy-urls.txt` заполнен; аудит старых адресов — все 301
- [ ] Цены, контакты, профили, рабочее время, ID GTM — заполнены в настройках
- [ ] Почта CF7: получатель и отправитель; SPF/DKIM домена разрешают отправку с сервера
- [ ] Фавикон/иконка сайта, обложки соцсетей, логотип в разметке
- [ ] Кеш страниц настроен (только Page Cache; исключения; принятые query strings; не кешировать 404)
- [ ] cron хостинга для `wp-cron.php` (если есть отложенные публикации)
- [ ] Бэкап старого сайта (файлы + база) скачан
- [ ] Деплой `production` в соседнюю папку → переключение папок → деплой без галочек
- [ ] Карта сайта в Вебмастер и Search Console; проверка 404 в течение 2–4 недель
- [ ] SEO-аудит и Lighthouse после запуска; отчёт сохранён

## Приёмка доработки (каждый PR)

- [ ] Изменение только через git; сгенерированные файлы пересобраны, не правлены руками
- [ ] CI зелёный (lint, PHPCS, установка с нуля); при изменении деплоя — локальный `docker compose up` прошёл
- [ ] Вёрстка проверена на настоящем телефоне (`phone.js`), а не только в эмуляции DevTools
- [ ] Проверено в редакторе и на сайте; 360/1280; светлая/тёмная; все языки
- [ ] Новые подписи — строки интерфейса, переведены
- [ ] Нет новых плагинов без обоснования в PR
- [ ] Нет секретов, личных данных, экспортов в диффе
- [ ] Комментарии «почему» у неочевидного; README обновлён, если меняется работа владельца
- [ ] Деплой на тестовый → проверка → слияние в main → деплой production → проверка страниц

## Аудит существующего сайта по этой методике

| Область | Вопрос | Как проверить |
|---|---|---|
| Архитектура | Данные в плагине, вид в теме? Тема живёт без плагина? | выключить плагин на копии |
| Редактор | Запись в редакторе = на сайте? Есть недействительные блоки? | `editor-validity.js`, сравнение |
| Код | `php -l`, escaping, nonce/capabilities в админке, префиксы | grep `echo \$`, PHPCS (WordPress) |
| Деплой | Повторяемый? Бэкап перед обновлением? Секреты в окружениях? | запуск дважды, чтение workflow |
| Контент | Владелец может поменять тексты, цены, меню, подписи без программиста? | пройти «где что править» |
| SEO | title/description, canonical, hreflang, карта, JSON-LD, 301 | `seo-audit.yml` |
| GEO | llms.txt, боты ИИ, автор-человек, FAQPage, крошки | раздел GEO отчёта |
| Скорость | Lighthouse mobile ≥ 90; LCP/CLS/TBT; кеш страниц | Lighthouse-выжимка |
| Доступность | контраст обеих тем, фокус, Esc, aria, h1 | Lighthouse a11y + сценарии + ручная клавиатура |
| Мобильная | нет горизонтальной прокрутки на 360 | `crawl.js 360` |
| Формы | валидация, антиспам, сохранение заявок, уведомления | `interact.js` |
| Аналитика | согласие до счётчиков, нет счётчиков на тестовом и у редакторов | DevTools → Network |
| Безопасность | `DISALLOW_FILE_EDIT`, нет экспорта/бэкапов в public_html, нет секретов в git | ls, `git log -p` |
| Документация | README актуален, TODO с владельцами | чтение |

Итог аудита — таблица «находка → приоритет (P0 ломает / P1 мешает / P2 улучшение) → где исправлять (код/админка)
→ владелец», код — PR, тексты — TODO.
