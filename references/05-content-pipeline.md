# 5. Конвейер контента: прототип → content.json → импорт

## Зачем

До запуска сайта тексты живут в прототипе/макете (HTML, JS-данные, markdown от копирайтера). Переносить
вручную 70 страниц на 3 языках — неделя работы и сотни ошибок. Поэтому контент собирается скриптом в
готовую разметку Gutenberg и ставится командой WP-CLI. После запуска источником становится админка.

```
project/ (прототип: i18n/*.js, data/*.js, *.html)
   │  node wordpress/tools/build-content.js
   ▼
wordpress/acme-core/content/content.json   ← разметка блоков, мета, ключи, языки, version
wordpress/acme-core/content/media/         ← фото, сертификаты
wordpress/acme/inc/strings-data.php        ← подписи интерфейса по языкам
   │  wp acme import [--force]   (запускает remote.sh при первой установке)
   ▼
WordPress: языки, медиа, разделы, страницы, записи, переводы, опции, формы, меню, обложки
```

## Сборщик

`tools/build-content.js` — Node без зависимостей (только `fs`, `path`, `vm`):

- данные прототипа загружаются в песочницу `vm` (файлы вида `window.X = {…}` выполняются как есть);
- разметка блоков — через `tools/lib/blocks.js`: `paragraph`, `heading`, `list`, `group`, `buttons`, `image`,
  `table`, `details`, `block(name, attrs, inner)`, `acme(name, attrs)` для блоков темы. Генераторы выдают
  **каноническую** разметку — ровно такую, какую сохранил бы редактор (порядок атрибутов, экранирование
  `--`, `<`, `>`, `&`, `"` в JSON атрибутов как в `serialize_block_attributes()`, классы `wp-block-*`).
  Иначе редактор покажет «Блок содержит неожиданное содержимое»;
- ссылки и ID, которых ещё нет, — **метки**, импортёр подставляет настоящие значения:
  `{{url:page:contacts}}`, `{{url:media:hero}}`, `{{id:svc:pochta}}`, `{{url:archive:acme_case}}`;
  у картинок временный ID (`7770001…`), импортёр заменяет на ID вложения;
- адреса: русские слаги — английскими словами из таблицы `RU_SLUGS` (ошибка, если ключа нет), у других
  языков — свои слаги (бесплатный Polylang не даёт одинаковые адреса разным языкам);
- суммы в текстах заменяются метками `{{price:key}}`, значения уходят в `content/prices.php`;
- выход детерминирован (одинаковый вход → байт-в-байт одинаковый файл) — CI пересобирает и делает
  `git diff --exit-code`;
- `version` в `content.json` увеличивается, когда меняются адреса или структура: тестовый сайт при деплое
  увидит новую версию и перезальёт контент сам.

Сгенерированные файлы коммитятся и **не правятся руками**; в `.vscode/settings.json` они исключены из поиска.

## Импорт

`wp acme import [--force]` (`inc/import/`, подключается только под `WP_CLI`; `cli.php` — порядок шагов, остальные
файлы — по шагу: записи, рубрики, медиа, меню, формы, языки, настройки, очистка):

1. Проверяет зависимости (Polylang, если языков больше одного), читает `content.json`.
2. Без `--force` и с опцией `acme_imported` — отказ с понятным сообщением.
3. `wp_set_current_user( <первый админ> )`, `kses_remove_filters()` (иначе вырежутся атрибуты блоков),
   `wp_defer_term_counting( true )`.
4. `--force` → `cleanup()`: удаляет **только** записи, вложения, формы и термины с мета `acme_imported`.
   Записи владельца не трогаются.
5. Шаги: языки → постоянные ссылки → медиа → разделы → записи → служебные страницы → связи переводов →
   подстановка меток → опции (роли, главная, страница блога, название) → формы CF7 → строки переводов →
   меню → обложки.
6. Каждая созданная запись: `acme_imported = 1`, `acme_key = <ключ>`, язык, мета из `content.json`.
7. `delete_option('rewrite_rules')` (правила пересоберутся с правилами языков), `acme_imported = дата`,
   `acme_content_version = version`.

`remote.sh` решает, когда импортировать:

| Ситуация | Действие |
|---|---|
| Опции `acme_imported` нет | `wp acme import` |
| Галочка `force_import` в деплое | `wp acme import --force` |
| Тестовый сайт и `version` в `content.json` ≠ `acme_content_version` | `wp acme import --force` (сам) |
| Иначе | «Контент уже импортирован — не трогаю» |

На боевом после запуска `--force` не запускается: он перезапишет правки владельца.

## Другие команды «создай, чего нет»

Каждый деплой вызывает команды, которые **только дополняют**:

- `wp acme seo [--force]` — настройки Rank Math один раз на версию, сброс кеша карты сайта (в каркасе);
- `wp acme menus [--force]` — меню по областям и языкам, если их ещё нет (в каркасе меню создаёт импорт;
  отдельная команда нужна, когда меню должны появляться и на уже работающем сайте);
- `wp acme covers [--force]` — обложки записям без изображения (модуль kalaganov5);
- `wp acme articles [--draft]` — статьи пакета (см. ниже), только отсутствующие (модуль kalaganov5).

Шаблон любой такой команды: проверить флаг/опцию/мету → сделать недостающее → записать отметку → вывести
одну строку «что сделано» (для лога деплоя).

## Статьи пакетом с отложенной публикацией

Если копирайтер сдаёт пакет статей (JSON/HTML):

- `tools/build-articles.js` превращает HTML в блоки: абзацы, заголовки, списки, таблицы; «Частые вопросы» —
  группа с `core/details` (из неё строится FAQPage); блок услуги и «Источники» — группы с классами; лид
  уходит в отрывок; абсолютные ссылки на сайт — в относительные;
- `wp acme articles`: рубрики по направлениям услуг (описание + услуга рубрики), статьи — отложенная
  публикация по одной в будний день в 10:00, направлениями по очереди; SEO-поля Rank Math, рубрика, услуга,
  «Читайте также», обложка; уже созданные статьи не трогает;
- ссылки на ещё не опубликованные статьи выводятся текстом, после публикации становятся ссылками
  (фильтр по `post_status` при выводе) — посетитель не попадает на 404;
- кеш страниц не будит WP-Cron, поэтому: раз в 10 минут при любом запросе к WordPress публикуются отложенные
  статьи с прошедшим временем + задание cron на хостинге (`wget -q -O /dev/null …/wp-cron.php?doing_wp_cron`).

## Перенос со старого сайта

`wp acme legacy <export.xml> [--update] [--dry-run] [--uploads-dir=…]`:

- читает WXR-экспорт (Инструменты → Экспорт → всё), переносит статьи, страницы, рубрики, мета Rank Math,
  изображения (из папки `uploads` на том же сервере или скачивая со старого домена, с повтором и отчётом
  о неудачах), пути файлов сохраняются — старые ссылки на картинки работают;
- новые слаги — по таблице соответствий `content/legacy-map.php` (транслит → английские слова);
- внутренние ссылки в текстах переписываются на новые адреса; пустые абзацы чистятся;
- таблица редиректов (`acme_legacy_map`) хранит **цель как ссылку на запись** (post ID, ключ услуги, роль
  страницы, архив, термин), а не адрес;
- повторный запуск ничего не дублирует (по старому ID); `--update` перезаписывает;
- экспорт не хранится в git (в нём черновики и e-mail) — кладётся на сервер в `~/acme-legacy/export.xml`
  (вне `public_html`); `remote.sh` переносит его из публичной папки, если положили туда по ошибке;
- CI переносит маленький тестовый экспорт (`tools/qa/legacy-sample.xml`) и проверяет статьи, файлы и 301.

Редиректы — см. 07-seo-geo.md.
