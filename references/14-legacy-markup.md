# 14. Перенос чужой вёрстки: HTML-шаблон, лендинг, экспорт из Figma или конструктора

Задача: есть готовая вёрстка (купленный шаблон, лендинг фрилансера, экспорт Webflow/Tilda/Figma-плагина,
старый сайт) — её нужно превратить в страницы этой системы так, чтобы владелец правил тексты в редакторе,
а вид совпадал с исходником. Это не «вставить HTML в блок»: результат — токены, core-блоки, блоки темы
со своим `style.css` и общие стили в `assets/css/`.

## Правило выбора: чем станет каждый кусок

| В исходной вёрстке | Чем становится у нас | Почему |
|---|---|---|
| Цвета, шрифты, отступы, радиусы, тени (в CSS-переменных, Sass-переменных или разбросаны по CSS) | токены в `tokens.css` + палитра `theme.json` | Один источник; свои цвета в редакторе выключены |
| Заголовки, абзацы, списки, цитаты, таблицы, картинки, кнопки | core-блоки (`heading`, `paragraph`, `list`, `quote`, `table`, `image`, `buttons`) | Владелец правит как в Word; разметка переживёт смену темы |
| Обёртки секций (`section > .container > …`) | `core/group` с `tagName: section`, классы `acme-section`, `acme-wrap` | Ритм секций и ширина — общие правила `site.css` |
| Сетка карточек с текстом, который пишут руками | `core/group` со стилем «Карточка» или блок `acme/cards` | Карточки-ссылки на записи — блок (ссылка хранится ID, а не адресом) |
| Карточки, которые повторяют данные записей (услуги, кейсы, отзывы, статьи) | блок темы, читающий записи (`get_posts`) или `core/query` + `acme/post-card` | Данные в одном месте; новая запись появляется сама |
| Аккордеон, FAQ, «спойлер» | `core/details` (в группе `.acme-faq` — FAQPage) | Работает без JS, доступен с клавиатуры, даёт разметку FAQPage |
| Табы | блок темы с атрибутом-массивом `items` + раздел в `site.js` | Интерактив с ролями `tablist/tab/tabpanel` и клавиатурой |
| Слайдер / карусель | блок темы: лента `scroll-snap` + кнопки в `site.js` (без Swiper/Slick) | Нет библиотек на всех страницах; не ломает LCP (см. 08) |
| Модальное окно | `<dialog>` в разметке блока + `showModal()` в `site.js` | Фокус, Esc и затемнение — из коробки браузера |
| Форма (любой «самописный» `form` с `action` на PHP-скрипт) | `acme/lead-form` (Contact Form 7, заявки, Telegram) | Антиспам, сохранение заявок, письма — уже решено |
| Шапка, меню, бургер, подвал | `acme/site-header`, `acme/site-footer` + меню WordPress | Меню правит владелец, на каждом языке своё |
| Иконки (sprite, icon-font, inline SVG) | `acme_icon( 'имя' )` — SVG с `currentColor` в `inc/markup.php` | Без шрифта иконок и лишних запросов; цвет из темы |
| Анимации появления (AOS, WOW, GSAP ScrollTrigger) | CSS `@keyframes` + `IntersectionObserver` в `site.js`, или убрать | Библиотеки анимаций — сотни КБ; уважать `prefers-reduced-motion` |
| jQuery-плагины (маски телефона, селекты, датапикеры) | нативные элементы (`type="tel"`, `<select>`, `type="date"`) или убрать | jQuery на сайте — минус к скорости ради мелочи |
| Bootstrap/Tailwind-классы в разметке | собственные классы `acme-*` и стили блоков | Классы фреймворка в базе — навсегда; CSS фреймворка — на каждой странице |
| Инлайн-стили (`style="…"`) | классы в CSS блока или `assets/css/`; в редакторе — стили блоков (`is-style-*`) | Инлайн-стиль в базе нельзя поменять из git |
| Тексты интерфейса (кнопка «Отправить», подписи форм, aria) | строки `acme_t( 'ключ' )` | Правятся в «Перевод строк», есть на всех языках |
| Счётчики, пиксели, чаты в `<head>` | GTM через `inc/analytics.php` (согласие на cookie) | Ничего до согласия; отложенная загрузка |

Если сомневаетесь, блок или core: **текст, который будет меняться, — core-блоки; разметка с данными или логикой — блок темы.**

## Порядок работы

1. **Инвентаризация.** Пройти исходник постранично и составить таблицу «секция → чем станет» (по правилу выше).
   Отдельным списком — все повторяющиеся компоненты (карточка, кнопка, бейдж) и все интерактивы.
   Список подписей интерфейса → ключи строк.
2. **Токены.** Вытащить цвета, шрифты, размеры шрифтов, отступы, радиусы, тени в `tokens.css`. Близкие значения
   слить (`#333`, `#343434` → один `--ink`). Тёмную тему придумать, если её нет: пары «фон — текст» на контраст.
   Шрифты — скачать woff2 локально (02-design-system.md).
3. **Базовый CSS.** Перенести только то, что описывает вид: общее — в `base.css`, `core-blocks.css`,
   `components.css`, остальное — в `style.css` блока; классы `acme-*`.
   Сброс браузера, сетку фреймворка, утилиты — не переносить: их заменяют `acme-wrap`, `acme-section`, `gap`.
4. **Блоки темы** для интерактивов и данных: `node wordpress/tools/new-block.js <имя> --attrs=…`,
   разметка — из исходника, тексты — из атрибутов или строк, JS — раздел в `site.js` через `init( root )` + `once()`.
5. **Шаблоны и паттерны.** Повторяющиеся страницы (услуга, кейс) — паттерн «полная страница» в `patterns/`.
6. **Контент.** Тексты исходника → исходные данные (`project/content/site.js`) → `build-content.js` → импорт.
   Если страниц мало — можно собрать в редакторе руками, но тогда это уже контент, а не код.
7. **Сверка.** Скриншоты исходника и нового сайта на 1280 и 360 px рядом; `crawl.js` (горизонтальная прокрутка,
   ошибки JS); `editor-validity.js` (блоки); Lighthouse исходника и нового сайта — новый не должен быть медленнее.
8. **Отличия от исходника** — раздел в README: что упрощено и почему (например, «слайдер на Swiper заменён лентой
   со scroll-snap: минус 140 КБ JS»).

## Чего не делать

- Не вставлять исходный HTML целиком в блок «HTML» или «Код»: владелец не сможет править текст, стили
  фреймворка утекут на сайт, разметка не пройдёт ни SEO-, ни a11y-проверки.
- Не тащить библиотеки исходника «на всякий случай»: каждая — минус к PageSpeed на всех страницах.
- Не переносить пиксель-в-пиксель то, что ломает доступность: серый текст с контрастом 3:1, кнопки-`div`,
  ссылки «нажмите здесь», `outline: none` без замены. Исправить и записать в «Отличия от исходника».
- Не оставлять тексты интерфейса в разметке блока — только через строки.
- Не копировать код из платных шаблонов и сборок, лицензия которых запрещает распространение (репозиторий
  может быть публичным): переносится вид и поведение, код пишется заново.

## Пример: секция «Преимущества» из лендинга

Исходник:

```html
<section class="features py-5 bg-light">
  <div class="container"><h2 class="text-center mb-4">Почему мы</h2>
    <div class="row">
      <div class="col-md-4"><div class="card p-4"><i class="icon-shield"></i><h3>Надёжно</h3><p>Гарантия 1 год</p></div></div>
      …
```

Результат — core-блоки, без классов Bootstrap:

```html
<!-- wp:group {"tagName":"section","className":"acme-section is-sunken"} -->
<section class="wp-block-group acme-section is-sunken"><!-- wp:group {"className":"acme-wrap"} -->
<div class="wp-block-group acme-wrap"><!-- wp:heading -->
<h2 class="wp-block-heading">Почему мы</h2>
<!-- /wp:heading -->
<!-- wp:group {"className":"acme-cards"} -->
<div class="wp-block-group acme-cards"><!-- wp:group {"className":"is-style-card"} -->
<div class="wp-block-group is-style-card"><!-- wp:heading {"level":3} -->
<h3 class="wp-block-heading">Надёжно</h3>
<!-- /wp:heading -->
<!-- wp:paragraph -->
<p>Гарантия 1 год</p>
<!-- /wp:paragraph --></div>
<!-- /wp:group --></div>
<!-- /wp:group --></div>
<!-- /wp:group --></section>
<!-- /wp:group -->
```

`py-5 bg-light` → `acme-section is-sunken`; `container` → `acme-wrap`; `row/col-md-4` → сетка `acme-cards`;
`card p-4` → стиль группы «Карточка»; иконка-шрифт → убрана или SVG через блок темы, если иконки нужны.
Сниппеты `acme-section`, `acme-p`, `acme-buttons` (`.vscode/acme.code-snippets`) дают эту разметку быстрее,
чем писать руками.
