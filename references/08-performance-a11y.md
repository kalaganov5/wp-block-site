# 8. Скорость и доступность

Цель: Lighthouse mobile ≥ 90 по Performance, ≥ 95 по Accessibility, Best Practices, SEO на ключевых страницах;
CLS ≈ 0; TTFB < 800 мс с кешем страниц.

## Что заложено в каркас

| Приём | Где | Зачем |
|---|---|---|
| Шрифты локально, variable woff2, `unicode-range`, `font-display: swap`, preload 1–2 файлов | `fonts.css`, `setup.php` | Нет внешних соединений; текст виден сразу |
| Эмодзи WordPress выключены | `setup.php` (`remove_action print_emoji_*`) | Минус скрипт и запросы к s.w.org |
| `should_load_separate_core_block_assets` → true | `setup.php` | CSS core-блоков только для блоков на странице |
| Один `site.js` с `strategy: defer`, без jQuery и библиотек | `setup.php` | Нет блокировки отрисовки; ~20 КБ вместо сотен |
| Версия статики = версия темы + `filemtime` | `acme_asset_ver()` | Можно кешировать CSS/JS на год: новый деплой → новый адрес |
| Кеш браузера на год + сжатие (`mod_expires`, `mod_headers`, `mod_deflate`) | `htaccess-cache.conf` → блок `.htaccess` | Повторные визиты без загрузки статики |
| Кеш страниц (W3 Total Cache: только Page Cache, Disk Enhanced) | вручную + сброс в `cache.php`/`remote.sh` | TTFB с ~1 с до ~100 мс на общем хостинге |
| YouTube — превью и кнопка; плеер `youtube-nocookie` по клику | `embeds.php` + `site.js` | Плеер — ~600 КБ скриптов и cookie до просмотра; страницы с видео падали до 52 |
| Встраивание чужой записи WP — обычная ссылка | `embeds.php` | Нет iframe и скрипта wp-embed |
| GTM после первого действия или через 3 с после load | `analytics.php` | Счётчики не влияют на TBT и LCP |
| Картинки: `width`/`height`, `loading="lazy"` кроме первого экрана, `decoding="async"`, `fetchpriority="high"` у LCP-картинки | `render.php`, core/image | Нет сдвигов (CLS), LCP грузится первым |
| Нет конструкторов страниц, слайдеров-плагинов, «оптимизаторов» | правило проекта | Каждый плагин добавляет CSS/JS на все страницы |

## Ловушки, на которые уже наступали

- **Прокручиваемая лента без `position: relative`**: абсолютные потомки (подпись `.screen-reader-text` в карточке,
  бейдж, тултип) привязываются не к ленте, а к странице — лента их не обрезает, и они стоят в конце её содержимого.
  На телефоне страница растягивается до конца ленты (на kalaganov5 — до 1480 px при экране 390): горизонтальная
  прокрутка, «плавающие» кнопки с `left/right` растягиваются на всю эту ширину. Любой контейнер с `overflow: auto`
  получает `position: relative`. Ловит `crawl.js` (scrollWidth > ширины экрана) — поэтому обход должен идти в CI,
  а не только вручную.
- **`scroll-behavior: smooth` + `scroll-snap` на ленте слайдера**: при загрузке лента плавно «доснапывается», и
  Chrome перестаёт фиксировать LCP — Lighthouse пишет `NO_LCP` и не ставит оценку. Плавную прокрутку кнопками
  делать в JS (`scrollTo({behavior})` с учётом `prefers-reduced-motion`), не в CSS ленты.
- **Lazy Load из плагина кеша** подменяет картинки заглушками и ломает замер Lighthouse — выключить, у темы своя.
- **Minify в плагине кеша** меняет порядок скриптов (согласие cookie → GTM) — выключить: сжатие уже есть.
- **Кеш базы/объектов на диске** на общем хостинге медленнее, чем без него.
- **«Принятые query strings»** в кеше: `utm_*`, `yclid`, `gclid`, `fbclid`, `ysclid` — иначе рекламный трафик
  получает страницы без кеша.
- **Не кешировать**: карты сайта, `llms.txt`, `wp-json/*`, 404 (на 404 работают редиректы), страницы для
  вошедших (редакторы видят свежее, GTM для них выключен).
- **Preload лишних шрифтов** отнимает полосу у LCP — только основное начертание основных алфавитов.
- **Определение языка браузера** в Polylang при кеше отдаёт всем один язык — выключено.

## Доступность (WCAG 2.1 AA)

- Контраст текста ≥ 4.5:1, крупного и иконок ≥ 3:1 — **в обеих темах**. Style Guide считает контраст пар из
  `tokens.css`. Пример исправления: плашка «New» в тёмной теме была 1.6:1 → тёмный текст, 9.5:1.
- Полупрозрачность серого текста не ниже `.85` (иначе контраст падает ниже 4.5:1).
- `:focus-visible` у всех интерактивных элементов; переход из оглавления ставит фокус на заголовок
  (`tabindex="-1"`), без рамки.
- Меню, мегаменю, язык, модальные окна: `aria-expanded`, `aria-controls`, `aria-pressed`, фокус внутрь при
  открытии, **Esc закрывает и возвращает фокус на кнопку**, клик снаружи закрывает.
- Один `<h1>` на странице; заголовки по порядку; `<main id="main">`; навигация — `<nav aria-label>`;
  крошки — `<ol>` и `aria-current="page"`.
- Кнопки без текста — `aria-label`; декоративные SVG — `aria-hidden="true"`; картинки — осмысленный `alt`
  (из медиатеки) или пустой для декоративных.
- `prefers-reduced-motion`: анимации и плавная прокрутка выключаются (CSS и JS).
- Цель касания ≥ 44×44 px; поля формы с `<label>`, ошибки связаны с полем и объявляются (`aria-live`).
- Язык фрагментов, отличающихся от языка страницы, — атрибут `lang`.
- Таблицы на мобильном — «карточками» с `data-label`, а не горизонтальной прокруткой на всю страницу.

## Мобильная вёрстка

- Нет горизонтальной прокрутки на 360 px — проверяет `tools/qa/crawl.js` на всех страницах.
- Широкие таблицы, код, видео в старых статьях — свой контейнер с `overflow-x: auto`, а не вся страница.
- Картинки — `height: auto` даже если в блоке записана высота (старые статьи с `width/height`).
- Брейкпоинт меню выбирается по реальной ширине пунктов на самом длинном языке (в kalaganov5 — 1100 px, а
  не 860 из макета).

## Замер

- **Actions → SEO-аудит**: Lighthouse mobile по списку ключевых страниц, выжимка — оценки, метрики,
  непройденные проверки и **конкретные элементы** (селектор + фрагмент разметки), которые их не прошли.
- PageSpeed Insights вручную — после деплоя, для главной и одной страницы каждого типа.
- Оценка 0 при живой странице — сбой замера (`runtimeError`, `NO_LCP`), а не сайт: смотреть `error` в выжимке.
