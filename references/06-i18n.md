# 6. Многоязычность

Если язык один — пропустить Polylang, но **оставить** механизм строк интерфейса (`acme_t()`): подписи всё
равно должны редактироваться в админке, а не в коде.

## Polylang (бесплатный)

- Основной язык — без префикса (`/`), остальные — папками (`/en/`, `/es/`). Настраивается импортом
  (`pll_options`: `force_lang = 1`, `hide_default = 1`, `rewrite = 1`, `browser = 0`).
- **Определение языка браузера выключено**: иначе кеш страниц отдаст главную на одном языке всем.
- Свои типы и таксономии переводимы: фильтры `pll_get_post_types`, `pll_get_taxonomies`.
- Ограничение бесплатной версии: **два языка не могут иметь одинаковый слаг**. Поэтому у каждого языка свои
  слаги: `/prices/` · `/en/pricing/` · `/es/precios/`; услуги: `/services/email/` · `/en/services/business-email/`.
- Связи переводов (`pll_save_post_translations`) ставит импорт; меню — по области на каждый язык (Polylang
  показывает области «… English»).

## Текущий язык

Одна функция плагина `acme_lang()`:

1. `?acmelang=xx` — только для превью блоков в редакторе (передаёт `editor.js`);
2. `pll_current_language()`;
3. язык текущей записи (`pll_get_post_language`) — для REST и превью;
4. основной язык.

Тема вызывает её через обёртку `acme_cur_lang()` (работает и без плагина).

## Строки интерфейса

Всё, что не является содержимым записи (кнопки, подписи формы, меню, cookie, сообщения об ошибках, слайдеры,
aria-label) — **строки** с ключом:

```php
acme_t( 'navPrices' );          // подпись на текущем языке
acme_e( 'formSubmit' );         // echo esc_html( acme_t(…) )
str_replace( '{n}', $n, acme_t( 'readMin' ) );   // параметры — {name}
```

Как устроено (`inc/strings.php`):

1. Значения по умолчанию — `inc/strings-data.php`: `[ 'ru' => [key => text], 'en' => […], … ]`
   (генерирует сборщик из прототипа или пишется руками).
2. На `init` в админке каждая русская строка регистрируется в Polylang: `pll_register_string( $key, $ru,
   '<сайт>', $multiline )` → видна в «Языки → Перевод строк».
3. `acme_t()` берёт перевод из Polylang (`pll_translate_string( $ru, $lang )`), если он отличается от
   оригинала; иначе — значение языка из `strings-data.php`; иначе — русское. Затем подставляет цены.
4. Импорт один раз записывает английские/испанские значения по умолчанию в переводы строк Polylang
   (`PLL_MO::import_from_db / add_entry / export_to_db`), чтобы владелец видел текущие тексты.
5. Строки для JS передаются в `window.ACME.s` через `wp_add_inline_script(..., 'before')` — только нужные ключи.

## Непереведённое

Если текст пока только на основном языке (например, 47 услуг на русском):

- копия на другом языке создаётся (меню и навигация работают), но в записи стоит флажок «Текст ещё не
  переведён» (`acme_untranslated`);
- такие страницы — `noindex, follow` (фильтр `wp_robots`), не попадают в карту сайта и **не указываются в
  hreflang** (фильтр `pll_rel_hreflang_attributes` удаляет их из списка у переведённых версий);
- фрагмент текста получает `lang="ru"` (класс `acme-lang-ru` → `render_block`), чтобы переносы и экранные
  дикторы работали правильно.

## Адреса

- Все адреса — латиницей; русские — английскими словами, а не транслитом (`/services/email/`, не
  `/uslugi/pochta-na-domene/`): короче, читаемо на всех языках, не превращается в `%D0%BF…`.
- Запасной вариант — транслит в `sanitize_title` (контекст `save`) для записей, у которых владелец не задал
  слаг. В README — просьба вписывать английский слаг в поле «Ссылка».
- Статьи — `/blog/<slug>/` (`permalink_structure = /blog/%postname%/`); свои типы — `rewrite.with_front:
  false`, чтобы `/blog/` не попал в `/services/`.
- Рубрики с кириллическим адресом автоматически получают латинский (`wp acme seo`), старый адрес ведёт 301.

## Числа, даты, часовой пояс

- Часовой пояс сайта задаётся при установке (`timezone_string`), формат даты — `j F Y`.
- Рабочее время в шапке («на связи») считается в браузере в часовом поясе владельца
  (`Intl.DateTimeFormat(..., { timeZone })`), а не сервера и не посетителя.
- Склонения («1 изменение / 2 изменения / 5 изменений») — три ключа строк и функция выбора формы.
