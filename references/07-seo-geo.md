# 7. SEO и GEO (поиск с ИИ)

SEO закладывается с первого шага, а не в конце: у каждой страницы с брифа есть запрос, адрес, title и
description, сборщик не пропускает пустые или повторяющиеся поля, а CI не даёт слить изменение, после
которого у страницы пропал title или появилось два H1.

| Этап | Что делается | Где |
|---|---|---|
| Бриф | Карта страниц: один запрос — одна страница, адрес, title, description | `12-checklists.md` |
| Контент | SEO-поля в исходнике; сборщик проверяет их | `project/content/site.js`, `tools/lib/seo-rules.js` |
| Импорт | Поля записываются в мету Rank Math | `inc/import/posts.php` |
| Деплой | Rank Math настраивается кодом, печатается самопроверка | `wp acme seo`, `inc/seo/*` |
| CI | SEO-гейт на установленном с нуля сайте | `tools/qa/seo-gate.js` |
| После запуска | SEO-аудит живого сайта раз в месяц | `seo-audit.yml`, `tools/qa/seo-crawl.js` |

## SEO-поля в исходнике контента

У каждой страницы, услуги и статьи на каждом языке: `seoTitle`, `seoDescription`, необязательный
`focusKeyword`. Импорт пишет их в `rank_math_title`, `rank_math_description`, `rank_math_focus_keyword`.

Сборщик (`node wordpress/tools/build-content.js`) завершается с ошибкой и называет страницу и язык, если:

| Правило | Почему |
|---|---|
| title 10–60 символов | Длиннее — поисковик обрежет; короче — не о чём ранжироваться |
| description 70–160 символов | Короче — поисковик подставит случайный кусок текста; длиннее — обрежет |
| title и description не повторяются в пределах языка | Одинаковые страницы конкурируют друг с другом |
| слаг — латиница, цифры, дефис | Адрес читается и не превращается в `%D0%…` |
| в тексте нет H1 | H1 выводит шаблон из заголовка записи — второй был бы дублем |
| у картинки есть `alt` | Описание для поиска по картинкам и экранных дикторов |

Длины считаются после подстановки цен `{{price:…}}`. Правила — чистые функции в `tools/lib/seo-rules.js`,
пределы — именованные константы с причиной.

**Один H1 на странице, и он приходит из шаблона** (`core/post-title`, уровень 1). Текст страниц и блоки темы
начинаются с H2. Поэтому заголовок правится в одном очевидном месте — поле заголовка записи.

## Rank Math, настроенный кодом

`wp acme seo` запускается при каждом деплое. Файлы `inc/seo/` — по одной задаче:

| Файл | Что делает |
|---|---|
| `rank-math.php` | `acme_seo_setup()`: настройки один раз на версию `ACME_SEO_VERSION`; `ACME_SEO_ENTITY` — person или company |
| `onboarding.php` | Без мастера, подключения аккаунта, статистики, рекламных уведомлений |
| `options.php` | Модули, шаблоны title/description, графа знаний, карта сайта, llms.txt |
| `indexnow.php` | IndexNow — только на открытом боевом сайте |
| `verification.php` | Коды Яндекс Вебмастера, Google, Bing из «Настройки → Сайт» → в настройки Rank Math |
| `social.php` | Обложка для соцсетей по языкам из `content/covers/site-<язык>.jpg` |
| `titles.php`, `descriptions.php`, `canonical.php` | title, description, canonical поверх шаблонов Rank Math |
| `closed.php` | `acme_seo_is_closed()` — одно правило для robots, карты сайта и llms.txt |
| `schema*.php`, `local-business.php`, `dates.php` | JSON-LD |
| `llms.php`, `robots.php` | llms.txt и robots.txt |
| `status.php`, `cli.php` | Самопроверка и команда `wp acme seo [--force]` |

**Настройки — один раз на версию.** Константа `ACME_SEO_VERSION`, опция `acme_seo_version`. Деплой ставит
настройки версии, если сохранённая версия меньше; дальше их меняют в админке, деплой не трогает. `--force`
ставит заново. Изменить настройки уже работающих сайтов: поднять версию, написать `acme_seo_options_v2()`
только с новыми ключами. Версию 1 после первого деплоя не менять — на работающих сайтах она не выполнится.

Что ставит версия 1:

- **модули**: включены `sitemap`, `rich-snippet`, `llms-txt`; выключены `analytics`, `content-ai`,
  `seo-analysis`, `link-counter`, `404-monitor`, `image-seo`, `local-seo` и интеграции с чужими плагинами —
  каждый добавляет запросы или шум в админке, а задачу решает тема или плагин данных;
- **мастер настройки пропущен**, аккаунт не нужен (`rank_math_registration_skip`): без этого Rank Math не
  выводит ни описаний, ни карты сайта, ни разметки; сбор статистики выключен;
- **title/description**: разделитель `|`, шаблоны по типам записей и рубрикам как запасной слой;
- **графа знаний**: person или company, название сайта, логотип (`custom_logo` или иконка сайта), профили;
- архивы авторов и дат выключены; поиск и пустые таксономии — `noindex`; метки — `noindex, follow`;
  вложения перенаправляются на запись; крошки Rank Math выключены (у темы свои);
- **разметка по умолчанию**: страницы и услуги — без своей схемы (её строит плагин), записи — `BlogPosting`;
- **карта сайта**: записи, страницы, свои публичные типы, рубрики, с картинками; без авторов, меток, вложений.

Кеш карты сайта сбрасывается, а **файлы удаляются вручную**: из WP-CLI (другой пользователь, чем у
веб-сервера) `invalidate_storage()` может молча оставить старые файлы.

**IndexNow** работает без аккаунта, но сам модуль не смотрит, открыт ли сайт. Поэтому `wp acme seo`
включает его только при `blog_public = 1` и `WP_ENVIRONMENT_TYPE = production` и выключает, если сайт закрыт:
тестовый сайт не должен сообщать поисковикам о своих страницах.

**Самопроверка** — пять строк в логе каждого деплоя:

```
SEO · Карта сайта: https://acme.example/sitemap_index.xml
SEO · Индексация: сайт открыт
SEO · Rank Math: 1.0.282
SEO · Модули Rank Math: sitemap, rich-snippet, llms-txt, instant-indexing
SEO · Коды вебмастеров: Яндекс — есть, Google — есть, Bing — нет
```

Каждое имя опции, модуля, фильтра и мета-поля Rank Math в каркасе сверено с его исходным кодом (версия
1.0.282). Новое имя — тоже только после проверки в исходниках: по памяти оно часто неверно, и Rank Math молча
игнорирует неизвестную опцию.

## Заголовки и описания по умолчанию

- Архивы своих типов и 404 — подписи из строк интерфейса на языке страницы.
- Списки со страницами — «— страница N» в title и description, иначе дубли.
- Заголовок длиннее 60 символов теряет хвост « | Имя сайта».
- Описание, если своего нет: подзаголовок страницы (`.acme-lead`) → отрывок → первый абзац не короче 60
  символов; до 155 символов, по слову.

## Закрытое от индексации

Одна функция `acme_seo_is_closed( $post )` (служебные страницы, непереведённые копии) — в `rank_math/frontend/robots`
(noindex), `rank_math/sitemap/entry` (не в карте), llms.txt (не в списке). Тестовый сайт закрыт целиком
окружением: `blog_public = 0`.

## JSON-LD (фильтр `rank_math/json_ld`)

| Тип страницы | Узлы |
|---|---|
| Главная, цены, контакты | Organization/Person, WebSite, WebPage |
| «О нас» / «Обо мне» | WebPage + AboutPage (компания) или ProfilePage (эксперт), `mainEntity` → сайт |
| Архив, блог | CollectionPage, BreadcrumbList |
| Услуга | Service (`provider`, `areaServed`, `serviceType`, `offers` из цены), BreadcrumbList |
| Статья | BlogPosting, автор — тот же Person/Organization сайта, а не логин WordPress |

- Служебные страницы — не `Article`: это не статьи, и поисковик показывал бы у них дату и автора.
- **LocalBusiness**: если сайт — компания и в настройках заполнены улица и город, узел организации получает
  адрес, телефон, часы работы, координаты. Пустые поля — ничего не выводится.
- **BreadcrumbList** — из тех же данных, что видимые крошки.
- **Даты**: `datePublished` — публикация; `dateModified` — дата существенного обновления (поле записи),
  иначе публикация. Обычная дата изменения WordPress не используется — она меняется от любой опечатки. То же
  значение — `og:updated_time` и `lastmod` в карте сайта.
- **FAQPage** строится из блоков «Вопросы и ответы» и включается константой `ACME_SEO_FAQ_SCHEMA`. Google
  убрал расширенные результаты FAQ для всех сайтов 7 мая 2026: в выдаче Google это ничего не даёт, разметка
  остаётся для других потребителей. HowTo не генерируется.
- Цена в `offers` берётся из текста цены («от 2 000 ₽»), валюта без знака — `ACME_SEO_CURRENCY`.

## GEO: чтобы ИИ-ассистенты понимали и цитировали сайт

- **`/llms.txt`** (модуль Rank Math): страницы, свои типы, статьи; описание — то же, что SEO-описание; без
  закрытых и юридических страниц; в конце — контакты и ссылки на другие языки.
- **robots.txt** (только если сайт открыт): явный `Allow` для ботов ИИ-ассистентов (GPTBot, OAI-SearchBot,
  ChatGPT-User, ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User, Google-Extended,
  Applebot-Extended); `Clean-param` для Яндекса (`utm_*`, `yclid`, `gclid`, `fbclid`, `ysclid`); ссылка на llms.txt.
- **Тексты**: первый абзац страницы сразу отвечает на главный вопрос; в услугах — что входит, сроки, цена.
  Это работа владельца — задачи в TODO по итогам аудита.

## Canonical и hreflang

- Rank Math (проверено на 1.0.282) с Polylang на странице блога второго языка дописывает язык дважды
  (`/en/articles/en/`). `canonical.php` строит canonical из перевода страницы записей + `page/N`.
- hreflang выводит Polylang; непереведённые копии из него удаляются (глава 06).

## SEO-гейт в CI

`node wordpress/tools/qa/seo-gate.js http://127.0.0.1:8080 --public` — после установки с нуля, на сайте с
`blog_public = 1`. Код 1 — только на ошибках, которые ломают индексацию или вид в выдаче:

- страница из карты сайта отвечает не 200; robots.txt или карта сайта не 200;
- нет title или meta description; одинаковые title;
- H1 не один;
- битая внутренняя ссылка;
- картинка без `alt`;
- JSON-LD — не JSON;
- на открытом сайте: `noindex` у страницы из карты, canonical отсутствует или ведёт на другой хост.

Остальное (короткое описание, нет обложки для соцсетей, мало текста) — предупреждения: их видно в сводке
запуска, но PR они не блокируют. Отчёт — `seo-gate-report/summary.md`. Правила — `tools/qa/lib/seo-gate-rules.js`.

## Перелинковка

Ссылки в тексте — вручную (Ctrl+K в редакторе), норма 3–5 на статью; сиротские страницы показывает SEO-аудит.
Автоматические блоки «Услуга по теме» и «Читайте также» в каркас не входят — эталон в kalaganov5
(`inc/post-links.php`): услуга подбирается по выбору в статье → совпадению основ слов → рубрике; две похожие
статьи — по основам слов заголовка, меток и начала текста.

## Перенос и 301

`inc/redirects.php`:

- срабатывает только на 404 (`template_redirect`, `is_404()`, приоритет 1) — существующие страницы не
  перехватываются, обычные страницы не замедляются;
- таблица — опция `acme_redirects` { '/старый/путь/' => цель }, её заполняет импорт из раздела `redirects`;
- цель — ссылка, а не адрес: `post` (ID), `key` (`acme_key` записи), `role`, `archive`, `url` → адрес
  вычисляется при запросе, поэтому смена слага или переимпорт не ломают редирект;
- `wp_safe_redirect( $url, 301, '<сайт>' )`;
- каждую пару проверяет CI, живой сайт — SEO-аудит по списку `tools/qa/legacy-urls.txt` (один 301 на страницу с 200).

При переносе большого сайта (модуль kalaganov5, `acme_legacy_map`) таблица шире: точные пути, старые слаги под
любой рубрикой, рубрики с `/page/N/`; метки и авторы старого сайта ведут в блог, `/amp/` — на основную страницу.

## После запуска домена

- Вставить коды подтверждения в «Настройки → Сайт», отправить `/sitemap_index.xml` в Яндекс Вебмастер и
  Google Search Console.
- 2–4 недели смотреть 404 и «исключённые» в вебмастерах; SEO-аудит — после каждого крупного деплоя и раз в месяц
  по расписанию (сравнивает с прошлым отчётом).
- Через месяц — каннибализация: статья ранжируется вместо услуги по коммерческому запросу.
