# Сайт Acme Site на WordPress

Блочная тема и плагин данных. Языки: основной — по адресу `/`, остальные — папками (`/en/`).

| Папка | Что это |
|---|---|
| `acme/` | Блочная тема: шаблоны, блоки темы, стили, скрипты, паттерны |
| `acme-core/` | Плагин данных: услуги, заявки, настройки, цены, SEO, аналитика, редиректы, импорт контента |
| `tools/build-content.js` | Собирает контент из `project/content/site.js` и `strings.js` для импорта, проверяет SEO-поля |
| `tools/check.js` | `npm run check` — все проверки кода одной командой |
| `deploy/` | `remote.sh` — установка, обновление и откат сайта; `deploy.sh` — выкладка по SSH; `manual.sh` — ручной деплой; `smoke.sh` + `pages.txt` — проверка страниц; `sync.sh` — копия боевого на тестовый |
| `local/` | Локальный сайт в Docker (тот же `remote.sh`), доступ с телефона (`phone.js`) |
| `tools/new-block.js` | Генератор нового блока темы |
| `tools/qa/` | Автопроверки: обход страниц, сценарии интерфейса, блоки в редакторе, SEO-аудит |

## Что нужно

- WordPress 7.0+, PHP 8.3+ (текущий Contact Form 7 требует 8.3). Плагины ставит деплой: Polylang, Contact Form 7,
  Rank Math, Cache Enabler (и Query Monitor на тестовом).
- Для разработки: Node 22+, Docker, Composer. Один раз: `npm install && composer install` — инструменты проверки и
  хук перед коммитом.
- Других плагинов не нужно: меню, cookie, слайдеры и формы сделаны в теме и плагине.

## Деплой (GitHub Actions)

- **CI** (`ci.yml`) — на каждый push и PR: `npm run check` и поиск секретов; установка сайта с нуля тем же скриптом, что
  на хостинге (PHP 8.3 и 8.4), повторный запуск, проверка страниц и SEO-гейт.
- **Деплой** (`deploy.yml`) — после зелёного CI выкладывает по SSH. Push в `main` → тестовый. Вручную: Actions →
  Деплой → Run workflow → `test` или `production` (боевой — только из `main`). Если после выкладки страницы не
  открываются — деплой сам вернёт прошлую версию темы и плагина. Откатить вручную — галочка `rollback`.
- **Ручной деплой без Actions** — `bash wordpress/deploy/manual.sh test` (или `production`); ключи — в
  `wordpress/deploy/manual-test.env` по образцу `manual.env.example` (в git не попадает).
- **Копия боевого на тестовый** (`sync.yml`) — база и загруженные файлы, только в эту сторону.
- **Дежурная проверка** (`health.yml`) — каждые 6 часов открывает страницы боевого сайта; не открылись — сообщение в
  Telegram. Нужны переменная репозитория `SITE_URL` и секреты `ALERT_TG_BOT_TOKEN`, `ALERT_TG_CHAT_ID`.
- **SEO-аудит** (`seo-audit.yml`) — раз в месяц и вручную: обход живого сайта и Lighthouse, сравнение с прошлым
  отчётом; отчёт в ветке `seo-reports`.

### Секреты

Settings → Environments → `test` и `production`, имена одинаковые, значения свои. Общие секреты репозитория не используйте.

| Секрет | Пример (тестовый) | Обязателен |
|---|---|---|
| `SSH_HOST`, `SSH_USER` | `1.2.3.4`, `acme_dev` | да |
| `SSH_KEY` или `SSH_PASSWORD` | приватный ключ целиком | одно из двух |
| `SSH_PORT`, `SSH_KNOWN_HOSTS` | `22`; строку печатает первый деплой | нет |
| `DEPLOY_PATH`, `SITE_URL` | `/home/a/acme/dev.acme.example/public_html`, `https://dev.acme.example` | да |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST` | из панели хостинга | для первой установки |
| `ADMIN_USER`, `ADMIN_PASSWORD`, `ADMIN_EMAIL` | администратор WordPress | для первой установки |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | копии заявок в Telegram | нет |
| `PHP_BIN`, `NOINDEX` | путь к PHP; `1` — закрыть боевой от поисковиков | нет |
| `PAGE_CACHE`, `AUTO_UPDATE_PLUGINS` (Variables окружения) | `0` — выключить кеш страниц; `1` — автообновление плагинов | нет |
| `SYNC_TEST_PATH`, `SYNC_TEST_URL` | только в `production`, для копии на тестовый | нет |

SSH-ключ: `ssh-keygen -t ed25519 -f acme_deploy -N ""`, `.pub` — в `~/.ssh/authorized_keys` на сервере, приватный — в `SSH_KEY`.

## Процесс: тестовый → боевой

1. Ветка → push → CI. Actions → Деплой → ваша ветка, `test` → проверка на тестовом.
2. Pull request в `main` → зелёный CI → Merge.
3. Actions → Деплой → `main`, `production`. Деплой сохранит копию базы в `~/acme-backups/` и обновит только тему и плагин.

Что можно править на боевом: тексты, страницы, услуги, медиатеку, меню, «Перевод строк», «Настройки → Acme Site»,
«Настройки → Цены», поля Rank Math, другие плагины. Чего избегать: правки файлов темы и плагина на сервере (деплой их
перезапишет), шаблоны в «Внешний вид → Редактор» (шаблон из базы перекрывает файл из git), `force_import` на боевом.

## Локальный сайт (Docker)

`docker compose up -d` → http://localhost:8080 (`admin` / `admin`). Первый запуск — 3–5 минут, ход: `docker compose logs -f setup`.
Тема и плагин подключены из репозитория: сохранили файл — обновили страницу. Ошибки PHP — `docker compose exec wordpress tail -f wp-content/debug.log`.
WP-CLI — `docker compose exec wordpress wp …`. С нуля — `docker compose down -v`. Порт занят — `ACME_PORT=8081 docker compose up -d`.
Кеш страниц локально выключен (`ACME_PAGE_CACHE=1` — включить). Проверить минимальный PHP — `ACME_PHP=8.3 docker compose up -d --build`.

## Кеш страниц и cron

Деплой ставит и настраивает Cache Enabler сам; кеш чистится при каждом деплое и при сохранении настроек, цен, меню.
Проверить: `curl -sI -H 'Accept: text/html' https://acme.example/` дважды — во втором ответе `X-Cache-Handler`.
При кеше страниц WP-Cron не просыпается: в панели хостинга добавьте задачу раз в 15 минут
`wget -q -O - https://acme.example/wp-cron.php` — иначе отложенные статьи не опубликуются.

### Телефон и база

- **Сайт на телефоне** (та же Wi-Fi): `ACME_BIND=0.0.0.0 docker compose up -d`, затем `node wordpress/local/phone.js` —
  адрес и QR-код (или задача VS Code «открыть для телефона»). Не открывается — проверьте VPN на компьютере
  (часто отрезает локальную сеть) и брандмауэр (Docker для частных сетей).
- **phpMyAdmin**: `docker compose --profile tools up -d` → http://localhost:8081.

### Новый блок темы

`node wordpress/tools/new-block.js price-table --title="Таблица цен" --attrs=title,lead,items` (или задача VS Code
«новый блок темы»). Блок сразу появится в редакторе в категории «Acme Site»; поля настроек строятся сами.
Сниппеты разметки: начните печатать `acme-` в шаблоне или паттерне.

## Редактор

Запись открывается в обычном редакторе: сверху поле заголовка (на сайте это главный заголовок страницы), ниже —
текст. Стили те же, что на сайте. Увидеть страницу целиком, с шапкой и подвалом, — кнопка «Показать шаблон» в
настройках записи; править текст можно и в этом режиме. Блоки темы показывают серверное превью и настраиваются в
панели справа; пустой блок показывает подсказку и на сайте ничего не выводит. Метки цен `{{price:hour}}` видны как есть.

## Как устроено и где что править

| Что | Где в админке |
|---|---|
| Тексты страниц | Страницы — редактор блоков |
| Услуги | Услуги; новая — «Добавить» → паттерн «Страница услуги»; поля меню и каталога — панель «Поля сайта» |
| Заявки | Заявки (сохраняются все отправленные) |
| Контакты, адрес и часы работы, Telegram-бот, GTM, служебные страницы | Настройки → Acme Site |
| Коды Яндекс Вебмастера, Google Search Console, Bing | Настройки → Acme Site |
| SEO-заголовок и описание страницы | Панель Rank Math в редакторе записи |
| Цены в текстах (`{{price:ключ}}`) | Настройки → Цены |
| Подписи интерфейса на всех языках | Языки → Перевод строк, группа «Acme Site» |
| Меню | Внешний вид → Меню (своё на каждом языке) |
| Почта для заявок | Контакт → формы «Заявка · …» → «Письмо» |

## Обновить контент до запуска

Правите `project/content/site.js` (тексты и SEO-поля) или `strings.js` (подписи) → `npm run build` → коммит. Сборщик
остановится с понятной ошибкой, если у страницы нет title или description, они слишком длинные или повторяются. На тестовом контент перезальётся,
если увеличить `version`; вручную — деплой с `force_import`. После запуска тексты правятся только в админке.
